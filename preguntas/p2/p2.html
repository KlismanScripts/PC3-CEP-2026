Problema 02

Cuadro Latino 4×4 – Tasa de Éxito de Financiamiento

01
Contexto de Experimento
Cuadrado Latino 4×4 – datos completos sin valor faltante

📌 Enunciado: FundBridge Analytics asesora emprendedores sobre qué tipo de plataforma de crowdfunding utilizar según la categoría de su proyecto. Se diseñó un Cuadrado Latino 4×4 que garantiza que cada tipo de plataforma (A: Equity, B: Reward‑based, C: Debt/Lending P2P, D: Donation‑based) se pruebe exactamente una vez en cada Categoría de Proyecto y en cada Trimestre, controlando así el efecto de la categoría (público inversor natural) y el efecto estacional (campañas de fin de año vs. inicio de año). La variable de respuesta es la Tasa de Éxito de Financiamiento (%), es decir, el porcentaje de la meta de recaudación alcanzado en el plazo establecido.

A continuación, se presenta la tabla de datos original del experimento:

Tecnología47.53 (A)37.17 (B)42.66 (C)36.51 (D)
Salud/Bienestar39.24 (B)42.59 (C)37.28 (D)49.73 (A)
Impacto Social41.60 (C)34.08 (D)47.37 (A)38.44 (B)
Industrias Creativas35.89 (D)47.03 (A)38.88 (B)43.64 (C)

🎯 Objetivo general

Evaluar si existen diferencias estadísticamente significativas en la Tasa de Éxito de Financiamiento (%) causadas por el tipo de plataforma (tratamiento), mientras se controla el efecto de bloque de categoría de proyecto y trimestre. Se identificará la plataforma que alcanza el mayor porcentaje de recaudación y se analizará la consistencia del experimento.

🧪 Factores estudiados

  • Factor Tratamiento (Plataforma): 4 niveles (A: Equity, B: Reward‑based, C: Debt/Lending P2P, D: Donation‑based).
  • Factor Bloque Fila (Categoría de Proyecto): 4 niveles (Tecnología, Salud/Bienestar, Impacto Social, Industrias Creativas).
  • Factor Bloque Columna (Trimestre): 4 niveles (T1, T2, T3, T4).
  • Variable de Respuesta: Tasa de Éxito de Financiamiento (% de meta alcanzada).
  • Diseño balanceado: No hay datos faltantes, el cuadrado es completo.

Formulación de Hipótesis
Contrastes estadísticos para cada factor (α = 0.05)

⚖️ Hipótesis a Contrastar

🔹 Plataforma (Tratamiento):
H₀: μA = μB = μC = μD (no hay efecto de la plataforma)
H₁: Al menos una plataforma genera una tasa de éxito media diferente.

Interpretación: evaluamos si el tipo de crowdfunding influye en el porcentaje de recaudación.

🔹 Categoría (bloque fila):
H₀: μTecno = μSalud = μImpacto = μCreativas
H₁: Al menos una categoría presenta tasa de éxito media distinta.
🔹 Trimestre (bloque columna):
H₀: μT1 = μT2 = μT3 = μT4
H₁: Al menos un trimestre produce tasa de éxito media diferente.
⚠️ Nota: El diseño es un cuadrado latino completo (sin datos faltantes). Todos los softwares reportan los mismos grados de libertad: GLError = (4-1)(4-2) = 6, GLTotal = 15.

# ==========================================
# 1. MATRIZ DE DATOS Y TRATAMIENTOS
# ==========================================
# Definición de los factores asegurando que R los trate como variables categóricas (factors)
Categoria <- as.factor(rep(c("Tecnologia", "Salud_Bienestar", "Impacto_Social", "Industrias_Creativas"), times = 4))
Trimestre <- as.factor(rep(c("T1", "T2", "T3", "T4"), each = 4))

# Tratamientos (Plataformas de Crowdfunding) leídos secuencialmente por columna
Plataforma <- as.factor(c(
  "A", "B", "C", "D", # T1
  "B", "C", "D", "A", # T2
  "C", "D", "A", "B", # T3
  "D", "A", "B", "C"  # T4
))

# Valores de la Variable de Respuesta (Tasa de Éxito %) por columna
TasaExito <- c(
  47.53, 39.24, 41.60, 35.89, # T1
  37.17, 42.59, 34.08, 47.03, # T2
  42.66, 37.28, 47.37, 38.88, # T3
  36.51, 49.73, 38.44, 43.64  # T4
)

# Ensamblaje del Data Frame
df_fundbridge <- data.frame(Categoria, Trimestre, Plataforma, TasaExito)

# ==========================================
# 2. MODELO ANOVA PARA CUADRADO LATINO
# ==========================================
# Fórmula: Respuesta ~ Filas + Columnas + Tratamientos
modelo_dcl <- aov(TasaExito ~ Categoria + Trimestre + Plataforma, data = df_fundbridge)

cat("==========================================\n")
cat("          TABLA ANOVA COMPLETA            \n")
cat("==========================================\n")
print(summary(modelo_dcl))
cat("\n")

# ==========================================
# 3. PRUEBAS POST-HOC DE TUKEY EXHAUSTIVAS
# ==========================================
# Calculamos las comparaciones múltiples con un nivel de confianza del 95% (alfa = 0.05)
tukey_resultados <- TukeyHSD(modelo_dcl, conf.level = 0.95)

# Función interna para formatear y añadir el diagnóstico dinámico a cada tabla
generar_diagnostico_tukey <- function(resultados_tukey, factor_nombre) {
  # Extraer la matriz de resultados del factor y convertir a data frame
  df_tukey <- as.data.frame(resultados_tukey[[factor_nombre]])
  
  # Añadir la columna de diagnóstico evaluando el p-value ajustado
  df_tukey$Diagnostico <- ifelse(df_tukey$`p adj` < 0.05, "SIGNIFICATIVO", "No Significativo")
  
  cat("------------------------------------------------------------\n")
  cat(paste("TUKEY:", toupper(factor_nombre), "\n"))
  cat("------------------------------------------------------------\n")
  print(df_tukey)
  cat("\n")
}

cat("==========================================\n")
cat("       RESULTADOS POST-HOC DE TUKEY       \n")
cat("==========================================\n")

# Ejecutar diagnóstico para cada uno de los factores evaluados
generar_diagnostico_tukey(tukey_resultados, "Plataforma") # Tratamientos
generar_diagnostico_tukey(tukey_resultados, "Categoria")  # Filas
generar_diagnostico_tukey(tukey_resultados, "Trimestre")  # Columnas

alfa = 0.05

def imprimir_tukey(factor_nombre, columna_df):
    """
    Función interna para ejecutar y formatear el resultado de Tukey HSD.
    La columna 'reject' de statsmodels evalúa automáticamente si la diferencia
    absoluta supera el límite HSD (True = SIGNIFICATIVO, False = No Significativo).
    """
    print("-" * 60)
    print(f"TUKEY: {factor_nombre.upper()}")
    print("-" * 60)
    tukey_result = pairwise_tukeyhsd(endog=df_fundbridge['TasaExito'], groups=columna_df, alpha=alfa)
    print(tukey_result)
    print("\n")

print("="*60)

Conclusiones
Recomendaciones finales sobre plataformas de crowdfunding
🎯 Plataforma (Tratamiento)

Se rechaza H₀ (p ≈ 1.5e-14). La plataforma A (Equity‑based) registra la mayor tasa de éxito (47.92%), seguida por C (Debt/Lending P2P, 42.62%), B (Reward‑based, 38.43%) y D (Donation‑based, 35.94%). La prueba de Tukey confirma que todas las diferencias entre plataformas son estadísticamente significativas. Por tanto, el orden de efectividad es claro: A > C > B > D.

📂 Categoría y Trimestre (Bloques)

Ambos factores de bloque resultaron altamente significativos (p ≈ 1.5e-09 y 1.3e-09, respectivamente). Esto confirma que controlar la categoría del proyecto y el trimestre fue esencial para reducir la variabilidad y aislar el efecto real de la plataforma. La estacionalidad y el tipo de público inversor influyen en el éxito de la campaña.

🧮 Consistencia entre softwares

Minitab, Excel, R y Python arrojan resultados prácticamente idénticos. La ausencia de datos faltantes garantiza grados de libertad uniformes y conclusiones robustas. Las pequeñas discrepancias en los decimales obedecen a redondeo.

🏆 Recomendación final

Se recomienda priorizar la Plataforma A (Equity‑based) para maximizar la tasa de éxito de financiamiento. No obstante, el análisis de negocio debe considerar que, si bien la plataforma A ofrece la mayor efectividad, sus comisiones podrían ser más elevadas. Para emprendedores que busquen un equilibrio, la plataforma C (Debt/Lending P2P) es la segunda mejor opción. Las plataformas B y D son significativamente inferiores y, por lo tanto, menos recomendables. El diseño experimental fue adecuado para controlar las fuentes de variabilidad (categoría y trimestre).
